# Docker Kinesis Local [![CI](https://github.com/saidsef/aws-kinesis-local/actions/workflows/ci.yml/badge.svg)](https://github.com/saidsef/aws-kinesis-local/actions/workflows/ci.yml) [![Charts](https://github.com/saidsef/aws-kinesis-local/actions/workflows/charts.yml/badge.svg)](https://github.com/saidsef/aws-kinesis-local/actions/workflows/charts.yml)

The image runs [kinesalite](https://github.com/mhart/kinesalite), a local emulator of the Amazon Kinesis Data Streams API, for development and CI. A Helm chart and Kustomize manifests deploy it to Kubernetes.

## Quick start

```bash
docker run -d -p 4567:4567 docker.io/saidsef/aws-kinesis-local:latest

export AWS_ACCESS_KEY_ID=test AWS_SECRET_ACCESS_KEY=test AWS_REGION=eu-west-1
aws --endpoint-url http://localhost:4567 kinesis list-streams
```

To run it on Kubernetes, install the Helm chart:

```bash
helm repo add kinesis https://saidsef.github.io/aws-kinesis-local/
helm upgrade --install kinesis kinesis/kinesis --namespace kinesis --create-namespace
```

## API coverage

kinesalite implements 17 Kinesis operations, which cover streams, shards, records, tags and retention periods. It does not implement enhanced fan-out, on-demand capacity mode or `UpdateShardCount`, and it answers those calls with `UnknownOperationException`. Kinesis Client Library (KCL) consumers use enhanced fan-out by default, so configure them for polling. [Supported operations](docs/supported-operations.md) lists every implemented operation and the KCL settings.
